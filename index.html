04 /Flow และคอขวด

แยกเวลาทำงานออกจากเวลารอ เพื่อเลือกแก้ขั้นตอนให้ตรงจุด

ความสูงแท่ง = log(1 + เวลาทำงานเฉลี่ย + เวลารอเฉลี่ย) · สัดส่วนซ้อนอิงเวลาจริง
ทำงานเฉลี่ยรอเฉลี่ย
คอขวด = ขั้นที่มี lostSec รวมสูงสุด โดย lostSec = waitSec + retries × durationSec + durationSec เมื่อ fail เป็นตัวชี้วัดภาระรอ/ทำซ้ำ ไม่ใช่เวลาที่ลดได้ทั้งหมด

06 /ข้อมูลและการเชื่อมต่อ

เริ่มเก็บหลักฐานการทำงาน โดยไม่บันทึกเนื้อหางานหรือข้อมูลส่วนบุคคล

Production เท่านั้น

สร้างคำสั่ง RUN_LOG ให้ Agent

เติม agentId และ Skill ที่ map ไว้ให้อัตโนมัติ

การใส่คำสั่งใน .md ไม่ได้ทำให้มี telemetry อัตโนมัติ เวลาต้องมาจากตัวจับเวลาของระบบ ห้ามให้ Agent เดาตัวเลข

นำเข้า RUN_LOG

หรือเลือกไฟล์ .json / .jsonl / .csv
CSV: 1 แถวต่อ 1 ขั้นตอน · ไฟล์ละไม่เกิน 10 MB

ตรวจข้อมูลทั้งชุดก่อนนำเข้า · ข้าม runId ที่ซ้ำเหมือนเดิม · ปฏิเสธ runId ที่ข้อมูลขัดกัน · ไม่เก็บ field นอก schema

แหล่งข้อมูลและทะเบียน

อัปเดตทะเบียน Agent / Skill
เฉพาะผู้ดูแล · ต้องมีหลักฐานการสร้าง · เพิ่ม/แก้เฉพาะ ID ที่ส่งมา ไม่ลบรายการอื่น
นิยามตัวชี้วัดและขอบเขตข้อมูลจริง
ไม่มีข้อมูล ไม่เท่ากับล้มเหลว

ก่อนอ่านฐานข้อมูล ค่าเป็น — หลังอ่านสำเร็จแล้วไม่พบงาน จำนวนงานจึงเป็น 0 ส่วนอัตราสำเร็จและเวลาเป็น — ไม่เติมตัวเลขแทนค่าที่ขาด

ทะเบียนแสดงเฉพาะรายการที่ผู้ดูแลยืนยันการสร้าง ไม่ใช้ชื่อจาก Roadmap หรือข้อเสนอเป็นหลักฐานว่า Agent ทำงานแล้ว

ความหมายตัวชี้วัด

อัตราสำเร็จ = success / งานทุกสถานะ กรองตาม startedAt ไม่ใช่อัตราสำเร็จของ execution_events รูปแบบเดิม การเรียก Skill นับ step ที่มี skillId ไม่เพิ่ม retry เป็น call ซ้ำ

เวลาประมาณต่องาน = Σ(durationSec × (1 + retries) + waitSec) อาจสูงกว่าเวลาจริงหากขั้นตอนขนานกัน ห้ามคาดเดาเวลาที่ไม่ได้วัด

แหล่งข้อมูลและสิทธิ์

ใช้ RPC agent_ops_operations_snapshot / write / register และตาราง agent_ops.operation_runs แยกจากตาราง HR ไม่ส่งเนื้อหางานหรือข้อมูลส่วนบุคคล

ไม่เก็บข้อมูลหลักหรือเซสชันใน localStorage ผู้ดูแลเพิ่มสมาชิกก่อนใช้งาน ปิดการลบประวัติผ่านหน้าจอ เพราะบันทึกเป็น append-only

การเชื่อม Runtime

การเปิด Dashboard ไม่ได้ทำให้ GPT หรือ Agent ส่ง log เอง ต้องต่อระบบที่รันงานเข้ากับ API ไม่มีการย้อนสร้างงานจากบทสนทนา

อ่านข้อมูลใหม่ทุก 60 วินาทีเฉพาะเมื่อเปิดหน้าและมีสิทธิ์ ไม่มีการเริ่ม Agent หรือสร้างข้อมูลจากการรีเฟรช

สำนักงานวิชาการ มหาวิทยาลัยศรีปทุม · ใช้บันทึกเพื่อปรับปรุงระบบ ไม่ใช่ประเมินบุคคลAGENT OPS / REAL ONLY / V2.2

เข้าสู่ระบบ Agent Operations

ใช้บัญชีของแอปนี้ การยืนยันตัวตนและสิทธิ์ Workspace เป็นคนละขั้นตอน ระบบไม่เพิ่มสิทธิ์ให้อัตโนมัติ

หรือใช้รหัสผ่านของแอป

รหัสของแอปอาจไม่ใช่รหัส Google หรือบัญชีจัดการ Supabase บัญชีที่เปิด MFA จะมีขั้นตอนยืนยันจากแอป Authenticator

ส่งคำขอตั้งรหัสใหม่สำหรับบัญชีเดิม ไม่สร้างบัญชีใหม่และไม่เพิ่มสิทธิ์ Workspace

เปิดอีเมลในอีกแท็บ แล้วคัดลอกลิงก์ตั้งรหัสใหม่มาเปิดในแท็บนี้ โดยแทน URL ในแถบที่อยู่ เพื่อให้คำขอ PKCE ตรงกับแท็บที่เริ่มต้น อย่าส่งลิงก์หรือรหัสยืนยันให้ผู้อื่น

การเปลี่ยนรหัสมีผลกับบัญชีเดียวกันในแอปอื่นที่ใช้ Supabase โครงการนี้ด้วย และไม่ยกเลิก MFA

ผ่านขั้นตอนแรกแล้ว บัญชีนี้เปิดการยืนยันสองขั้นตอน กรุณาใช้รหัสจากแอป Authenticator ที่ผูกไว้ ไม่ใช่รหัสจากอีเมล

ไม่มีอุปกรณ์เดิม: หยุดขั้นตอนนี้และใช้กระบวนการกู้คืนบัญชีขององค์กร หน้านี้ไม่ปิด MFA ให้

ตั้งรหัสใหม่ที่ไม่ซ้ำกับรหัสซึ่งส่งในแชท รหัสจะส่งตรงไปยัง Supabase Auth และไม่บันทึกไว้ใน Dashboard
